# RankKernel Schema Module — Adversarial Audit (raw)

Audit scope: `src/Modules/Schema/**`, `src/Modules/Metadata/{Context,MetaPayload}.php`,
`src/Admin/{SchemaMetabox,SchemaSettingsPage}.php`, `src/Admin/Views/schema-metabox.php`,
`tests/Unit/Schema*.php`, `tests/Unit/BreadcrumbsSchemaIntegrationTest.php`, `tests/Unit/FaqBlockTest.php`,
`tests/Unit/HowtoBlockTest.php`, and the claimed state in `docs/ROADMAP.md` / `docs/competitor-analysis/feature-parity-matrix.md`.
Audit only, no source modified. Every claim below carries a `file:line` citation.

## Verdict

The Schema engine is genuinely implemented and, in the majority of cases, more complete than the parity matrix says: a real generator/piece architecture (`Generator.php:53`, `:63`), 29 registered pieces (`SchemaModule.php:290-329`), one `application/ld+json` script per page (`SchemaModule.php:282`), a structural normalizer that dedupes `@id` and prunes dangling internal refs (`GraphNormalizer.php:140`, `:172`), working per-type gating and defaults (`SchemaHelpers.php:319`), a real metabox with import/export and a raw custom-JSON box (`SchemaMetabox.php:881`, `:989`), and server-rendered FAQ/HowTo blocks (`FaqBlock.php:146`, `HowtoBlock.php:190`). JSON is valid and correctly escaped for the script context — `JSON_HEX_TAG|APOS|QUOT|AMP` are set on `wp_json_encode` (`SchemaModule.php:272-275`) and the breakout test passes (`test_render_escapes_script_breakout`, `SchemaProductionTest.php:843`) — so malformed custom JSON cannot break the page or produce invalid JSON on the front end. The most serious real defect is not an XSS or a parse break but silent data loss: when the custom-JSON textarea is submitted with invalid JSON, the save path sets `custom` to `[]` and overwrites the stored payload, destroying any previously saved custom schema while only setting an easily-missed redirect flag (`SchemaMetabox.php:661-720`; this behaviour is even asserted by `test_save_invalid_custom_json_error_path`, `SchemaMetaboxTest.php:558`, specifically `:586-587`). Several matrix rows also materially disagree with the code — most notably "Custom schema builder (blank canvas)" = PARTIAL when no builder exists (only a raw textarea, `Views/schema-metabox.php:77`) and "SiteNavigationElement" = PARTIAL when no such piece exists anywhere in `src/` (grep empty) — while the matrix *understates* delivered capabilities (Speakable, About/Mentions, term `CollectionPage`, WooCommerce field reads, JSON-file import). The claimed inventory is numerically accurate: 26 supported types (`SchemaTypes.php:38-65`), 26 registry entries (`SchemaTypes.php:97-124`), and 29 registered pieces (`SchemaModule.php:296-324`).

## Actual inventory

Counts verified by parsing the source, not the docs.

- **Selectable/supported types = 26.** Enumerated from `SchemaTypes::SUPPORTED` (SchemaTypes.php:38-65):
  `Article, BlogPosting, NewsArticle, WebPage, FAQPage, HowTo, Product, Recipe, Event, Service, VideoObject, ImageObject, Book, Course, JobPosting, SoftwareApplication, MusicRecording, LocalBusiness, Review, Movie, ClaimReview, Dataset, PodcastEpisode, Carousel, QAPage, ItemList`.
- **Registry entries = 26.** `SchemaTypes::PIECES` (SchemaTypes.php:97-124) has one entry per supported type; enforced by `test_registry_maps_every_supported_type_to_a_piece` (SchemaProductionTest.php:212).
- **Registered pieces = 29.** `SchemaModule::getGenerator` (SchemaModule.php:296-324) registers 29 instances; 29 piece classes live in `src/Modules/Schema/Pieces/` excluding `SchemaHelpers.php` (helper, not a piece).
- **Composition of the 29:** 24 type-owning pieces + 5 always-on/utility pieces. The three article types share one piece id (`article`), so 26 types collapse to 24 distinct type-owning piece ids; the extra 5 are `organization`, `website`, `breadcrumb`, `person`, `custom` (SchemaTypes.php:97-124; SchemaModule.php:296-324).
- **The claim "26 types across 29 pieces" (ROADMAP.md:138, feature-parity-master.md:38) is numerically correct**, though "29 pieces" counts the helper-adjacent non-type pieces and the shared article piece, and the gate doc's "30 pieces" (feature-parity-master.md:1684) counts `SchemaHelpers` as a piece.
- **Block count:** 2 (`rankkernel/faq`, `rankkernel/howto`) registered via `SchemaModule::boot` (SchemaModule.php:219-220).
- **No discrepancy found in the count claim.** Discrepancies are in *capability* claims, not counts.

## Gap classification

**P0 — none.** No XSS/breakout (JSON_HEX flags + passing breakout test, SchemaModule.php:272; SchemaProductionTest.php:843), no invalid JSON emitted, no fatal path found.

**P1**
- Malformed custom-JSON save silently destroys the previously stored custom schema (`custom=[]`, then full payload overwrite) — data loss with only a redirect flag as feedback. SchemaMetabox.php:661-678, :685-720; baked in by SchemaMetaboxTest.php:586-587.
- Any node value that fails `wp_json_encode` (e.g. invalid UTF-8 bytes reaching a node) makes `render` return without output, silently dropping the entire schema graph with no fallback or log. SchemaModule.php:275-279.

**P2**
- Canonical override breaks `@id` interlinking: Webpage uses `pageBase()` (canonical-first) while Article/Breadcrumb/Faq use `permalink()`, so `mainEntityOfPage` and `breadcrumb` refs become dangling and are pruned when a canonical differs from the permalink. SchemaHelpers.php:399-437; ArticlePiece.php:121, :157; BreadcrumbPiece.php:117, :158; GraphNormalizer.php:215-223.
- Custom JSON with an array `@type` is comma-joined into a single invalid type string (e.g. `"Article,NewsArticle"`), which survives the normalizer because it is a non-empty string. CustomJsonPiece.php:153-158; GraphNormalizer.php:57-73.
- FAQ/HowTo/QAPage posts carry both a page-level `BlogPosting` (Article piece) and the companion page type, contradicting the "never two competing primaries" invariant asserted in ArticlePiece's docblock. ArticlePiece.php:26-31, :92-96 vs FaqPiece.php:63, HowtoPiece.php:67.
- `VideoObject.contentUrl` and `thumbnailUrl` are emitted after only `trim()`, unlike every other URL field which runs `esc_url_raw`/`SchemaHelpers::httpUrl`. VideoPiece.php:109-113, :143-147 vs SchemaHelpers.php:479-517.

**P3**
- No systematic graph-integrity test asserting every internal `@id` ref resolves; only publisher/provider pruning is covered. SchemaProductionTest.php:905.
- Reusable block references (`core/block`) are not resolved for FAQ rows (documented limitation). FaqPiece.php:208-212.
- Roadmap/parity-only capabilities (below) — no shipping defect, backlog.

## Tests that would be needed

1. **Canonical vs permalink graph integrity:** set a payload `canonical` differing from the permalink and assert Webpage `@id`, Breadcrumb `@id`, Webpage `breadcrumb` ref, and Article `mainEntityOfPage` ref still resolve (currently would prune). No existing test sets `canonical` in a schema graph (grep: only SchemaMetaboxTest.php:292/:383).
2. **Custom-JSON data preservation:** submit invalid custom JSON and assert the previously stored `custom` is retained rather than wiped. The current test asserts the destructive behavior (SchemaMetaboxTest.php:586-587), so this test must redefine the contract.
3. **Encode-failure degradation:** feed a node containing invalid UTF-8 (or a filter-injected resource) and assert a defined fallback (skip node vs suppress graph) instead of silent loss. SchemaModule.php:275-279 is untested.
4. **Custom array `@type`:** assert array types are rejected or normalized to a valid single type (not comma-joined). CustomJsonPiece.php:153-158 is untested.
5. **Generic graph-integrity sweep:** for each of the 26 types, assert every `@id`-only ref in the merged graph targets an id present in the same graph and that no duplicate `@id` exists (currently only publisher/provider cases are covered).
6. **Single-primary assertion including companions:** assert the intended primary set for FAQPage/HowTo/QAPage posts (BlogPosting + FAQPage, etc.) so the invariant is explicit rather than implied.
7. **Count guard:** a test asserting `count(SUPPORTED) === 26` and `count(registered pieces) === 29` so the claim cannot silently drift (registry mapping is guarded by SchemaProductionTest.php:212, but the raw counts are not).
8. **URL-scheme validation for VideoObject:** assert `contentUrl`/`thumbnailUrl` reject `javascript:`/`data:` like the HowTo block path does (HowtoPiece.php:534-558).
9. **JSON validity under adversarial strings:** assert `json_decode` of the rendered script succeeds for nodes containing `</script>`, quotes, ampersands, and Unicode across all type pieces (only custom JSON is currently covered).
