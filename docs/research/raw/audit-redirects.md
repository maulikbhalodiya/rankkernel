# Audit: Redirects Module (rankkernel)

Scope: `src/Modules/Redirects/*`, `src/Admin/RedirectsPage.php`, `src/Admin/Views/redirects.php`, `assets/js/redirects-admin.js`, `tests/Unit/Redirects*.php`, `docs/ROADMAP.md`, `docs/competitor-analysis/feature-parity-matrix.md`, `docs/architecture/redirects*.md`. Read-only audit; no source or test file was modified.

## Verdict

The six match modes, five status codes, deterministic precedence, normalisation, loop/chain safety analysis, CSV import/export, slug watcher, one-response runtime, admin security controls and the single-table schema are all genuinely implemented and backed by a large, adversarial test suite — the DONE rows of the parity matrix are accurate for these. Two real defects break headline claims: (1) `RedirectsModule::register()` calls `RedirectCache::invalidateAll()` on **every** request (`RedirectsModule.php:151`), because `ModuleManager::bootEnabled()` invokes `register()` each request (`ModuleManager.php:160`, hooked on `init` at `rankkernel.php:152-157`), so the validator is bumped per request and the object-cache/transient match cache is **always stale on the next request** — the advertised "cache-first / cache hit = 0 queries" only holds within a single process and never across requests; (2) the admin Redirects screen is registered unconditionally on `admin_menu` (`Plugin.php:141`, `AdminMenu.php:211-223`) with no module-enabled gate, so with the module OFF the submenu still renders and `RedirectsPage::render()` runs `paginate()` against a table that was never created (`RedirectsModule::register()` returns before `ensureTables()`), producing failing queries. Also confirmed genuinely absent: scheduled activation/expiration (schema has no date columns, settings has no keys, no runtime logic), and case-insensitive matching (the `$caseInsensitive` normaliser parameter and hash folding exist but no caller, column or UI uses it), and capture substitution (`$1` sends literally). The module is default OFF and, on the frontend when disabled, costs zero hooks and zero redirect queries.

## Query and cost analysis

**Disabled module (frontend):** zero redirect hooks and zero redirect queries. `RedirectsModule::register()` and `::boot()` return immediately (`RedirectsModule.php:138,158`), and `ModuleManager::bootEnabled()` never calls them (`ModuleManager.php:154-161`). Baseline cost remaining is the single shared autoloaded `get_option('rankkernel_modules')` in `ModuleEnableMap::__construct` (`ModuleEnableMap.php:30-32`) plus class autoload/instantiation. Proven by `RedirectsModuleTest::test_disabled_module_boots_zero_hooks` (asserts `add_action`/`add_filter`/`update_option` never).

**Enabled module, per request (before any dispatch):** because `bootModules()` runs on `init` every request (`rankkernel.php:152-157`), `RedirectsModule::register()` runs every request and costs:
- `RedirectTable::ensureTables()` → `exists()` → one `SHOW TABLES LIKE` (`RedirectTable.php:93-101,67-86,81`), cached for the request.
- `RedirectsSettings::ensureSchema()` → `get_option('rankkernel_redirects_settings')` (`RedirectsSettings.php:106-117`), a non-autoloaded option (`RedirectsSettings.php:110,142`).
- `$settings->set(['schema_ok'=>true])` → `update_option` on the first request only, no-op afterwards (identical value) (`RedirectsSettings.php:125-147`).
- **`RedirectCache::invalidateAll()` → `update_option(VALIDATOR_OPTION, time().'_'.uniqid())` on every request** (`RedirectsModule.php:151`, `RedirectCache.php:146-148`). This is one DB write per page view and makes every previously stored payload stale.

**Cache hit (in-request):** `Redirector.php:156` → `RedirectCache::get()` (`RedirectCache.php:83-106`): one `get_option(VALIDATOR_OPTION)` (`RedirectCache.php:96`) plus one `readStore` (`RedirectCache.php:219-234`, `wp_cache_get` or `get_transient`). Zero rule-table reads (`RedirectRepository::lookup` not called). Proven for rule reads by `RedirectsRedirectorTest::test_cache_hit_runs_zero_rule_queries`. **Cross-request it can never hit** because `register()` bumped the validator (`RedirectCache.php:99-101` returns null).

**Cache miss:** `all_patterns`/`lookup` run. Exact-only miss = one indexed `get_row` (`Matcher.php:71` → `RedirectRepository.php:104-118`). Pattern miss = one exact `get_row` + one bounded `get_results` for patterns (`Matcher.php:77` → `RedirectRepository.php:183-221`), i.e. one-to-two rule reads (`RedirectsPatternBoundTest::test_matcher_cold_miss_costs_two_indexed_reads_then_one`; `RedirectsRedirectorTest::test_cold_miss_exact_runs_one_indexed_lookup`). Then the cache is warmed (`Redirector.php:162`, `RedirectCache.php:114-125`) with the current validator — stale by the next request.

**On a fired redirect:** `HitCounter::record` touches memory only (`HitCounter.php:45-60`); `shutdown` flush writes one `UPDATE` per touched rule (`HitCounter.php:65-88`), proven never to occur before the response by `RedirectsDispatchCacheTest::test_counters_never_write_before_response` and coalescing by `::test_multiple_hits_coalesce_to_one_update_per_rule`.

Net: the architecture doc's "cache hit = 0 queries" (`docs/architecture/redirects.md`, `docs/ROADMAP.md:109`) is false in production on two counts — the per-request `SHOW TABLES`/option reads/write baseline, and the per-request validator bump that retires the cached match.

## Security review

- Capability checks — **PASS**: `manage_options` gates the menu (`AdminMenu.php:216`) and `requireAccess()` (`RedirectsPage.php:783-790`); proven by `RedirectsAdminTest::test_form_save_without_capability_dies`, `::test_row_action_without_capability_dies`, `::test_bulk_without_capability_dies`.
- Nonces — **PASS**: distinct nonce per action (`RedirectsPage.php:46-71`), verified before every mutating handler (`:904,1260,1288,1325,1374,1419`), fields in the view (`Views/redirects.php:140,282,373,407`); proven by the six `*_bad_nonce_dies` tests. Minor: the `false === $verified` guard at `:794` is unreachable in production since `check_admin_referer` dies on failure.
- SQL preparation — **PASS**: all reads/writes use `$wpdb->prepare`, `$wpdb->insert/update/delete`, or integer-cast id lists (`RedirectRepository.php:112-115,319-325,442,455,473,531,652,699,731,947`; `HitCounter.php:82-85`); ORDER BY column is allowlisted (`RedirectRepository.php:507-511`); LIKE needles escaped (`RedirectRepository.php:958-966`). No user input reaches raw SQL.
- Sanitisation of stored source/target — **PASS**: source normalised on every path (`RedirectRepository.php:990-1001`); target validated by `DestinationValidator` on admin (`RedirectsPage.php:1146-1152`), CSV (`CsvHandler.php:474`) and slug watcher (`SlugWatcher.php:311`); admin output escaped (`Views/redirects.php:323,334`). Note `RedirectRepository::insert/update` themselves accept any non-empty target (`RedirectRepository.php:1004-1016`), so correctness depends on callers; the runtime re-validates regardless (`Redirector.php:232-236`).
- Open redirect / attacker-controlled target — **PASS**: external hosts rejected unless present in the empty-by-default `rankkernel/redirect/allowed_hosts` filter, matched case-insensitively but exactly (`DestinationValidator.php:99-131`; `Redirector.php:263-282`); same-host absolute folds to a relative path; protocol-relative URLs resolve to an external host and are rejected (`DestinationValidator.php:139-165`); the dispatcher sends only the validated destination (`Redirector.php:192`). Proven by `RedirectsSecurityTest::test_send_never_emits_raw_external_row`, `::test_protocol_relative_external_blocked_without_allowlist`, `RedirectsDestinationValidatorTest::test_http_external_requires_allowlist`.
- CRLF / header injection — **PASS**: control chars rejected at save and at send (`DestinationValidator.php:64-66`; `Redirector.php:232-236`), proven by `RedirectsSecurityTest::test_send_never_emits_raw_crlf_row` and `RedirectsDestinationValidatorTest::test_crlf_rejected`. The preserved incoming query is appended without explicit validation (`Redirector.php:247-253`), but `wp_redirect()` sanitises CR/LF/percent-encoded CR/LF and PHP rejects raw CRLF in the request line; there is no dedicated test for a CRLF-bearing query.
- Unsafe schemes — **PASS**: `wp_allowed_protocols` allowlist plus case-insensitive scheme check (`DestinationValidator.php:68-76`), proven by `RedirectsSecurityTest::test_scheme_case_variants_rejected_at_save`, `::test_padded_javascript_rejected_at_save`.
- Regex/wildcard injection and DoS — **PASS**: wildcard glob is `preg_quote`d then anchored, so user metacharacters stay literal (`Matcher.php:414-424`, `RedirectsSecurityTest::test_wildcard_metacharacters_match_literally`); regex is length-capped and count-capped and fails closed on error (`Matcher.php:374-403,433-454`).
- CSV injection — **PASS**: `sanitize_cell`/`escape_cell` prefix a quote for `= + - @ tab CR` (`CsvHandler.php:338-363`), proven both directions by `RedirectsSecurityTest::test_formula_cells_neutralized_both_directions`.
- Path traversal — **PASS (by literal round-trip)**: `/a/../b` is stored and matched literally; no file access occurs (`RedirectsSecurityTest::test_traversal_input_round_trips_literally`).
- Admin availability when module OFF — **FAIL (availability, not auth)**: `addRedirectsPage` is registered unconditionally (`Plugin.php:141`, `AdminMenu.php:211-223`) and `RedirectsPage::render()` queries the redirect table on the admin load hook (`RedirectsPage.php:349-360`) even though a disabled module never created it (`RedirectsModule.php:138`); visiting the screen with the module OFF yields failing SQL.
- Disabled-state frontend cost — **PASS**: zero hooks/queries as above.

## Gap classification

- **P0** — none. No remote-code/privilege, data-loss, or exploit path found; save-to-send validation and capability/nonce/SQL controls hold.
- **P1** — `RedirectsModule::register()` invalidates the match cache on every request (`RedirectsModule.php:151` via `ModuleManager.php:160`), so the advertised cache-first cost is never realised across requests and every page view performs an extra non-autoloaded option write; this falsifies a headline claim and adds write amplification.
- **P2** — the Redirects admin screen is not gated by the module-enabled map (`Plugin.php:141`, `AdminMenu.php:211-223`), so a disabled module still renders a screen that queries a non-existent table.
- **P2** — the runtime has no cycle/hop guard (`Redirector.php:156-197`); inconclusive loops admitted by the admin (`RedirectsPage.php:963-976`) and CSV (`CsvHandler.php:600-605`) paths can bounce a browser indefinitely even though each server request terminates.
- **P2** — internal destinations lose their trailing slash (`Normalizer.php:93-95` via `DestinationValidator.php:154`), which can add a core canonical hop for `/new/`-style URLs.
- **P3** — scheduled activation/expiration is entirely absent but is a documented later roadmap item (matrix PLANNED `:254`; ROADMAP P2 steps 1.5.6 and 1.7.5 at `docs/ROADMAP.md:307-308,347-348`), so it does not belong to the current step.
- **P3** — case-insensitive matching is unimplemented despite normaliser/hash support (`Normalizer.php:101-103,140`), and capture substitution is unimplemented (`Redirector.php:171`).
- **P3** — `paginate` search uses unindexed `source/target LIKE` (`RedirectRepository.php:899`), admin-only and bounded.
- **P3** — import lacks an `is_uploaded_file()`/MIME check (`RedirectsPage.php:1398-1404`), and `docs/ROADMAP.md:108` retains stale two-table wording.
