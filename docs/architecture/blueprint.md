# RankKernel — Architecture Blueprint

> **The Free, Zero-Bloat Open-Source SEO Engine for WordPress**
>
> Status: Design specification only. No implementation, no code files. Every design decision traces to a verified competitor weakness (cited audit), a proven pattern to adopt (cited), or explicit engineering judgment (labeled `JUDGMENT`).

| Field | Value |

### Four Pillars

1. **No paywalls.** Every feature listed in this blueprint ships free, forever. No "Pro" tier, no credit packs, no upsell banners. (See `feature-matrix.md §6`: both competitors monetize redirects, schema builders, AI, and analytics behind paid tiers. We give them away.)
2. **Hard-gated modules.** A module that is off is *never instantiated*, so it registers *zero hooks* and adds *zero cost*. When a module is on, its expensive lookups are *cache-first*. We never claim "zero-query redirects" — that is false and indefensible. The accurate claim is: **zero cost when the module is disabled; cache-first lookup when enabled** (see `gap-analysis.md §4` counter-design RM1; `rankmath-audit.md §1` finding 4 for the proven `can_load_module` pattern we improve on).
3. **Single-row metadata + full uninstall purge.** All per-object SEO data lives in one post-meta row (`_rankkernel_meta_data`) and one term-meta row (`_rankkernel_term_data`), versus competitors' 25–45 rows per post (see `feature-matrix.md §6`: Yoast ~25 keys, Rank Math ~45 keys). Uninstall offers a user-choice full purge of options, meta, and tables (see `yoast-audit.md §1` finding 1 and `rankmath-audit.md §1` finding 8: both competitors retain all data by default).
4. **Open / transparent / zero telemetry.** 100% GPLv2-or-later, source on a public repo, no external requests except the single API the user explicitly configures (their own AI provider key, or IndexNow). No Mixpanel, no rankmath.com phone-home, no my.yoast.com tracking (see `feature-matrix.md §6`: Yoast and Rank Math both make admin external calls; we make none by default).

### Accuracy Rule (binding)

> Performance claims in this project must be **defensible**. We state: *"A disabled module costs zero — its class is never loaded and registers no hooks. An enabled module uses a cache-first lookup and degrades to at most one targeted query on a cache miss."* We **never** claim "zero-query redirects" or "zero database overhead" in any absolute sense. Where a query is unavoidable, we name it and bound it. (See `gap-analysis.md §4` RM1 counter-design and `rankmath-audit.md §6d` for the real per-request cost we are honest about.)

## B. Goals & Non-Goals

### B.1 Performance Targets (measurable budget)

| Metric | Target | Basis / citation |
|---|---|---|
| DB queries for meta on a rendered page | **≤ 1** (`get_post_meta` on the single key) | `gap-analysis.md §4` Y4 counter-design: "per-post single-key meta read = 1 query" |
| DB queries when **all optional modules off** | **0** (frontend) | `gap-analysis.md §4` RM1: copy `can_load_module`, avoid Yoast's always-on DI container (Y1) |
| Sitemap cache | **ON by default** | `gap-analysis.md §4` Y7 counter-design; Yoast ships it OFF (`yoast-audit.md §1` finding 4) |
| Admin assets | Screen-gated only; never enqueued on every admin page | `rankmath-audit.md §1` finding 9 (RM does this well); Yoast enqueues `admin-global` everywhere (`yoast-audit.md §1` finding 10) |
| Frontend CSS/JS | **Zero** except editor (Gutenberg) screens | `feature-matrix.md §6`: both competitors keep frontend clean; we extend the guarantee to "no frontend asset unless editing" |
| TTFB overhead (cached-object setups) | **≤ 1 ms** measurable target | `JUDGMENT`: aspirational ceiling; proven via the benchmark protocol in B.3, not asserted blindly |

### B.2 Benchmark Protocol (to PROVE claims vs Yoast / Rank Math)

We publish a repeatable comparison. Methodology:

1. **Fixed dataset.** `N` posts (default N = 1,000) + `M` terms (default M = 200), generated by a WP-CLI seed script. Same dataset loaded under (a) Yoast free, (b) Rank Math free, (c) RankKernel with all modules off, (d) RankKernel with all modules on.
2. **Query count.** Query Monitor (`qm/queries` or `get_num_queries()`) captured on a cached front page render (object cache warm). Report median over 20 hits.
3. **Memory.** `memory_get_peak_usage(true)` at `shutdown`, logged to error log, median over 20 hits.
4. **TTFB.** `curl -s -o /dev/null -w '%{time_starttransfer}'` against a warmed page, median over 20 hits, on a stock local LEMP stack.
5. **Uninstall purge.** After deactivate+delete with the purge option on, assert `wp_postmeta` has zero `_rankkernel_*` rows, `wp_options` has zero `rankkernel_*` rows, and no `wp_rankkernel_*` tables exist.
6. **Publishable chart.** A `docs/benchmarks/` markdown table + SVG bar chart, regenerated each release. Numbers are *measured*, never estimated. (See `feature-matrix.md §6` "We Win Here" #6: zero-query disabled modules is the headline claim we must be able to defend.)

### B.2b Example Expected Results Table (illustrative shape, NOT measured claims)

This is the *shape* of the published comparison, filled with real numbers at release time. The "RankKernel (modules off)" column is the one we can defend hardest.

| Scenario | Frontend DB queries | Peak memory (MB) | TTFB overhead (ms) |
|---|---|---|---|
| Yoast free (stock) | ~6–8 (indexable + breadcrumb + replace-var re-resolution) | ~12 | ~3–6 |
| Rank Math free (redirects on) | ~2–3 (redirect cache + match) | ~10 | ~2–4 |
| **RankKernel (all optional modules OFF)** | **0** | **~6** | **≤1** |
| RankKernel (all modules ON, warm cache) | ≤1 (single meta read) + sitemap cache hit | ~7 | ≤1 |

> The two RankKernel rows are bounded by design (§A accuracy rule, §C.5 hard gate, §E single-pass). The competitor rows are *estimates from the audits* (`yoast-audit.md §3` DB triggers; `rankmath-audit.md §6d`) and must be re-measured against the actual installed versions at release. We never publish a competitor number we have not reproduced.

### B.3 Non-Goals (explicitly out of scope for v1)

- **Analytics dashboards** (GSC/GA4). Defer to Site Kit bridge. (See `feature-matrix.md §5`: both vendors' analytics are paid or capped; we do not rebuild them in v1.)
- **Keyword rank tracking.** Out of scope v1 (`feature-matrix.md §5`).
- **Addon store / marketplace** in v1. Helper add-ons (WooCommerce, Headless bridge) may ship later as separate free plugins, but no in-dashboard store (`Custom WordPress SEO Plugin Blueprint.md` Part 2, Option A: single main plugin, helper add-ons only for niche integrations).
- **News / Video sitemaps.** Phase-2 candidate only (`feature-matrix.md §3`).
- **NLP/semantic entity scoring.** The original blueprint floated "Semantic NLP Scoring"; we keep readability + structure checks client-side and defer semantic scoring (`Custom WordPress SEO Plugin Blueprint.md` Phase 3). Not a v1 differentiator.

## C. Bootstrap & Module System

### C.1 Two-Phase Boot

```
plugins_loaded (priority 10)  ──►  register services, parse module registry,
                                    evaluate per-module conditionals ONCE
        │
init (priority default)       ──►  boot enabled modules (instantiate + registerHooks)
        │
wp_head / rest_api_init / etc ──►  module hooks fire only if module is enabled
```

- **Phase 1 (`plugins_loaded`, priority 10):** the main file requires the Composer autoloader, constructs the `Plugin` singleton, registers core services (Settings, Migrations, REST, ModuleManager), and reads the cached module-enable map **once**. No module class is instantiated yet.
- **Phase 2 (`init`):** `ModuleManager` instantiates only modules whose `isEnabled()` returned true in phase 1, then calls `registerHooks()` on each.

**No DI container.** Plain PSR-4 classes + an explicit factory inside `Plugin`. (See `gap-analysis.md §2`: Yoast's Symfony DI container is compiled on *every* frontend request — Y1. We reject that. `gap-analysis.md §4` Y1 counter-design: "Plain PSR-4 classes + ModuleManager registry; no container compile.")

### C.2 Guarded Main File

```
SPEC (main file rankkernel.php):
  if ( ! defined( 'ABSPATH' ) ) { exit; }
  // PHP + WP requirement checks BEFORE autoload:
  if ( version_compare( PHP_VERSION, '8.1.0', '<' ) ) { add_action('admin_notices', ...); return; }
  if ( version_compare( $wp_version, '6.5', '<' ) )   { add_action('admin_notices', ...); return; }
  // On missing requirements at activation -> register_activation_hook deactivates self.
```

The main file is a **procedural entry** (WPCS-checked, see §M). All logic lives in `src/` namespaced classes (PSR-12-checked).

### C.3 Plugin Singleton (container-lite)

```
SPEC (RankKernel\Plugin):
  final class Plugin {
    private static ?Plugin $instance = null;
    private array $services = [];          // core services (Settings, Migrations, REST, ModuleManager)
    private array $modules  = [];          // enabled module instances only
    public static function getInstance(): Plugin
    public function registerCoreServices(): void
    public function bootModules( ModuleManager $mm ): void
    public function get( string $id ): mixed   // service locator, NOT a DI container
  }
```

`JUDGMENT`: a service locator is sufficient and avoids the DI-compile cost we are explicitly rejecting. It is "container-lite" by design, not a full container.

### C.4 ModuleInterface

```
SPEC (RankKernel\Modules\ModuleInterface):
  interface ModuleInterface {
    public function getId(): string;            // e.g. 'redirects'
    public function getName(): string;          // human label for UI
    public function isEnabled(): bool;          // reads cached settings map
    public function getPriority(): int;         // boot/register order
    public function dependsOn(): array;         // array of module ids required
    public function register(): void;           // wire services (no hooks yet)
    public function boot(): void;               // registerHooks() — only if enabled
  }
```

### C.5 ModuleManager (the hard gate)

```
SPEC (RankKernel\Modules\ModuleManager):
  final class ModuleManager {
    /** @var array<string,ModuleInterface> */
    private array $registry = [];
    private array $enabledMap = [];             // id => bool, warmed once from rankkernel_modules

    public function register( ModuleInterface $m ): void
    public function evaluateAll(): void          // runs isEnabled() ONCE, caches result
    public function bootEnabled(): void          // instantiate + boot() only enabled
    public function isOn( string $id ): bool     // reads cached map, never re-queries
    public function get( string $id ): ?ModuleInterface
  }
```

**The hard gate (improving on Rank Math's `can_load_module`):**

Rank Math proves the pattern: when a module is off, `can_load_module()` returns false and the class is never instantiated, so its constructor (which registers every hook) never runs → zero hooks leak (`rankmath-audit.md §1` finding 4; `rankmath-audit.md §2.4`; `rankmath-audit.md §9`). We adopt and improve it with three additions:

1. **Per-module conditionals evaluated ONCE** at `plugins_loaded`, cached in `ModuleManager::$enabledMap`. No re-evaluation per request (`gap-analysis.md §4` RM1 counter-design).
2. **Settings-cache warm read.** The enable map is read from a single autoloaded option `rankkernel_modules` (array of enabled ids) — one `get_option` at boot, not per-module option reads.
3. **Dependency declaration.** `dependsOn()` is enforced at boot; a module whose dependency is off is forced off and noted in the UI. (Rank Math's registry has *no* `dep_modules` — `rankmath-audit.md §2.4`: "No module in the registry declares a dep_modules key." We fix that gap.)

> **Result:** module OFF = class never instantiated = zero hooks = zero DB cost. This is the headline differentiator (`feature-matrix.md §6` "We Win Here" #6).

## D. Data Layer Design (THE Differentiator)

### D.1 Single-Key Post Meta

One row per object. The entire SEO payload is a JSON object:

```
SPEC (post-meta key: _rankkernel_meta_data, value = JSON):
{
  "title": "",
  "description": "",
  "canonical": "",
  "robots": {
    "index": true,
    "follow": true,
    "noarchive": false,
    "noimageindex": false,
    "nosnippet": false,
    "max_snippet": null,
    "max_image_preview": null,
    "max_video_preview": null
  },
  "og":   { "title": "", "description": "", "image": "", "image_id": 0, "type": "" },
  "twitter": { "card": "summary_large_image", "title": "", "description": "", "image": "", "image_id": 0 },
  "focus_keywords": [],
  "schema": [],
  "flags": { "pillar": false, "cornerstone": false, "breadcrumb_title": "" }
}
```

**Rationale:** 1 row + 1 `get_post_meta` call vs competitors' 25–45 rows (`feature-matrix.md §6`: Yoast ~25 `_yoast_wpseo_*` keys, Rank Math ~45 `rank_math_*` keys). WP's own meta cache handles repeat reads within a request, so a single key also collapses their N-query meta reads into one.

**`register_meta` with `auth_callback` (fixes Rank Math's antipattern):** We register the key so it is REST-exposed and capability-checked, instead of Rank Math's custom `/updateMeta` bulk endpoint that bypasses WP meta registration (`rankmath-audit.md §8c`; `gap-analysis.md §2`: "No register_meta at all — custom POST /updateMeta bulk endpoint bypasses WP meta registration").

```
SPEC (registration, in Metadata module register()):
  register_meta( 'post', '_rankkernel_meta_data', [
    'type' => 'object',
    'single' => true,
    'show_in_rest' => [
      'schema' => [ 'type' => 'object', 'properties' => [ /* title, description, ... */ ] ],
    ],
    'auth_callback' => static fn() => current_user_can( 'edit_post', get_the_ID() ),
  ] );
```

Yoast *does* register meta with `auth_callback` (`yoast-audit.md §2.1`: `register_meta('post', '_yoast_wpseo_' . $key, ...)`). We adopt that clean pattern and extend it to a single object key.

### D.2 Term & User Meta

- Term meta single key: `_rankkernel_term_data` (same JSON shape, minus post-only fields). Mirrors the post design; collapses Rank Math's per-term `rank_math_*` rows (`rankmath-audit.md §2.1`).
- User meta single key for per-user prefs (e.g. AI key, analysis dismissals): `_rankkernel_user_prefs`.

### D.3 Options (flat groups, autoload discipline)

| option | autoload | contents |
|---|---|---|
| `rankkernel_settings` | **yes** (small) | global defaults: title/desc templates, social profiles, webmaster codes, module-independent config |
| `rankkernel_modules` | **yes** | array of enabled module ids (the warm-read enable map) |
| `rankkernel_db_version` | **no** | versioned migration ledger |
| per-module heavy data | **no** | e.g. `rankkernel_ai_keys`, `rankkernel_indexnow_key`, `rankkernel_robots_backup` |

Discipline: only the two small always-needed options autoload. Heavy payloads are `autoload=no` (see `gap-analysis.md §4` Y10/RM3 counter-design: "Flat settings array, single option, autoload=no for large payloads"). This directly attacks Rank Math autoloading all four `rank-math-options-*` groups on every request (`rankmath-audit.md §1` finding 3) and Yoast's `wpseo_taxonomy_meta` single autoloaded blob (`yoast-audit.md §2.2`).

### D.4 Custom Tables (ONLY when module enabled)

Tables are created lazily when a module is toggled on (mirroring Rank Math's `Installer::create_tables([$module])` per-module creation — `rankmath-audit.md §2.3`: "tables created only when those modules are switched on"). **Zero required tables for v1 core.**

```
SPEC (wp_rankkernel_redirects) — created only if redirects module enabled:
  id            BIGINT UNSIGNED AUTO_INCREMENT PK
  source_url_hash VARCHAR(64) NOT NULL UNIQUE     -- hash of normalized source
  source        TEXT NOT NULL
  target        TEXT NOT NULL
  code          ENUM('301','302','307','410','451') NOT NULL
  regex         TINYINT(1) NOT NULL DEFAULT 0
  hits          BIGINT UNSIGNED NOT NULL DEFAULT 0
  created       DATETIME NOT NULL
  -- lean: no serialized blob (unlike RM's `sources` longtext, rankmath-audit.md §6b)

SPEC (wp_rankkernel_redirects_cache) — cache-first lookup table:
  id            BIGINT UNSIGNED AUTO_INCREMENT PK
  hash          VARCHAR(64) NOT NULL              -- hash of request URI
  redirect_id   BIGINT UNSIGNED NOT NULL
  KEY (hash)

SPEC (wp_rankkernel_404_log) — created only if 404 module enabled:
  id            BIGINT UNSIGNED AUTO_INCREMENT PK
  uri_hash      VARCHAR(64) NOT NULL INDEX         -- indexed (RM uses uri(191), rankmath-audit.md §6i)
  uri           TEXT NOT NULL
  referer       VARCHAR(255) DEFAULT ''
  user_agent    VARCHAR(255) DEFAULT ''
  created       DATETIME NOT NULL
```

**404 prune policy (fixes Rank Math's truncate-at-limit):** Rank Math `DB::add` *truncates the whole table* when count ≥ limit (`rankmath-audit.md §6i`; `gap-analysis.md §1` RM5). We instead **prune by age (retention days) AND by row count (oldest-first DELETE)**, never a blanket truncate. `JUDGMENT`: history loss on a hard limit is a data-integrity bug, not a feature.

### D.5 Uninstall / Purge

- A settings checkbox (default = **ASK**, i.e. prompt at delete) controls purge.
- On purge: delete all `rankkernel_*` options, all `_rankkernel_*` post/term/user meta, and drop `wp_rankkernel_*` tables.
- Contrast: Yoast `register_uninstall_hook(..., '__return_false')` is a deliberate no-op (`yoast-audit.md §1` finding 1, §2.5); Rank Math's `rank_math_clear_data_on_uninstall` filter defaults to false (`rankmath-audit.md §1` finding 8, §2.6). We make clean uninstall the *default-ask*, not the exception (`feature-matrix.md §6` "We Win Here" #7).

## E. Frontend Head Pipeline Design

### E.1 Single HeadRenderer, one pass

```
SPEC (RankKernel\Modules\Metadata\HeadRenderer):
  class HeadRenderer implements ModuleInterface {
    public function boot(): void {
      add_action( 'wp_head', [ $this, 'render' ], 1 );          // early, single emit
      add_filter( 'pre_get_document_title', [ $this, 'title' ], 10 );
    }
    public function render(): void   // emits ALL tags in ONE loop
    public function title( $title )  // presenter for core title machinery
  }
```

All tags (title, description, robots, canonical, prev/next, OG, Twitter, Slack, webmaster, schema) are emitted in **one pass** from a single built context object. No per-tag action spaghetti.

### E.2 Single-Pass TagsReplacer (memoized)

Yoast's `replace_vars()` runs **4+ times per page** — once per presenter — re-scanning tokens and re-resolving `%%var%%` each time, including repeat `get_terms()`/`get_post_meta()` calls (`yoast-audit.md §3` perf criticism; `gap-analysis.md §1` Y3). We fix this:

```
SPEC (RankKernel\Modules\Metadata\TagsReplacer):
  class TagsReplacer {
    /** @var array<string,string> memoized by (context_hash . '|' . field) */
    private array $memo = [];
    public function replace( Context $ctx, string $template, string $field ): string {
      $key = $ctx->hash() . '|' . $field;
      return $this->memo[$key] ??= $this->doReplace( $ctx, $template );
    }
  }
```

One resolved string per (context, field), reused by every presenter. No duplicate DB hits for the same token.

### E.3 Lazy Breadcrumbs

Yoast computes breadcrumbs generating **4–6 extra `wp_yoast_indexable` queries per request even when the theme never renders them** — used only for one schema property (`yoast-audit.md §1` finding 7, §3; `gap-analysis.md §1` Y2). We compute breadcrumbs **only when** (a) the theme/block requests them via `rankkernel/breadcrumbs`, or (b) the Schema module needs the `Breadcrumb` piece. Otherwise: zero breadcrumb queries.

### E.4 Context built once

A single `Context` object is built per request from **one meta read + one term read** (when on a term archive). No global `$wp_query`/`$post` mutation, no `wp_reset_query()` dance (Yoast does `wp_reset_query()` on every head call — `yoast-audit.md §3`). All escaping per WPCS (`esc_html`, `esc_attr`, `esc_url`).

## F. Sitemap Design

### F.1 Rewrite + intercept (adopt Yoast's proven pattern)

We mirror Yoast's pre-`get_posts` interception + exit-before-theme (`yoast-audit.md §4` Step 3):

```
SPEC (RankKernel\Modules\Sitemaps\Router):
  add_action( 'init',        [ $this, 'addRewriteRules' ], 1 );
  add_filter( 'query_vars',  [ $this, 'addQueryVars' ] );
  add_action( 'pre_get_posts', [ $this, 'intercept' ], 1 );   // redirect() -> output -> exit
  // on sitemap/xsl request: remove_all_actions('widgets_init'), remove_all_actions('wp_footer'), exit
```

- Rewrite rules: `sitemap_index.xml$` → `index.php?sitemap=1`; `([^/]+?)-sitemap([0-9]+)?\.xml$` → `sitemap=$1&sitemap_n=$2`; `([a-z]+)?-?sitemap.xsl$` → `xsl=$1`.
- Query vars: `sitemap`, `sitemap_n`, `xsl`.
- `redirect_canonical` filter returns false for sitemap/xsl (avoid trailing-slash redirect).

### F.2 Providers & pagination

- Providers per post type, per taxonomy, authors. Direct `$wpdb` for the heavy listing (Yoast uses late-row-lookup `$wpdb` — `yoast-audit.md §4` query strategy); we follow that for scale.
- **1000 entries per page** (`yoast-audit.md §4`: `wpseo_sitemap_entries_per_page` default 1000).
- Image tags inline (`<image:image>`), XSL served via `readfile` with long cache headers (mirror `yoast-audit.md §4` Step 5).

### F.3 Cache ON by default (adopt Yoast's validator, flip the default)

Yoast's sitemap transient cache ships **OFF** (`apply_filters('wpseo_enable_xml_sitemap_transient_caching', false)` — `yoast-audit.md §1` finding 4, §4 cache lifecycle). We adopt Yoast's **validator-based invalidation design** (global + per-type validators, queued invalidation flushed on `shutdown`) but **default it ON** (`gap-analysis.md §4` Y7 counter-design).

```
SPEC (cache behavior):
  - Storage: transient + object-cache group `rankkernel-sitemaps`
  - Validator: rankkernel_sitemap_validator_global + per-type validator (option-backed)
  - Invalidation: on save_post / edited_terms / user_register / option update -> queue -> flush on shutdown
  - Default: ENABLED (filter rankkernel/sitemap/enable_cache defaults true)
  - IndexNow ping hook point: do_action('rankkernel/sitemap/ping') on publish (cache-warm, not a real engine ping)
```

> **Honesty note:** like both competitors, our "ping" is cache-warming + the `Sitemap:` robots directive (`yoast-audit.md §4` ping flow; `rankmath-audit.md §5e`: RM's `hit_index` is not a real search-engine ping). We do **not** claim to ping Google/Bing directly. IndexNow (a real ping) is a separate module (`instant-indexing`).

## G. Redirects & 404 Design

### G.1 Hook point + justification

Rank Math hooks `do_redirection` on **`wp` priority 11 on every frontend request**, costing 1–2 DB queries minimum even for non-redirected URLs (`rankmath-audit.md §1` finding 5, §6a; `gap-analysis.md §1` RM1). We use a **single cache-first lookup at `template_redirect` (early priority, e.g. 1)** instead of `wp@11` every request:

- `template_redirect` fires once, after the main query is resolved and before template render — the correct point to issue a redirect.
- **Cache-first:** look up `wp_rankkernel_redirects_cache` by request-URI hash. Hit → redirect immediately (0 meta/redirect-table queries beyond the cache hit, which is object-cache backed).
- **Miss:** one targeted match query against `wp_rankkernel_redirects` (by `source_url_hash`), then warm the cache row. Bounded to **one query on a cold miss**.
- **Module OFF = zero hooks.** The `Redirects` class is never instantiated (`can_load_module` gate), so `template_redirect` is never touched.

```
SPEC (RankKernel\Modules\Redirects\Redirector):
  public function boot(): void {
    add_action( 'template_redirect', [ $this, 'maybeRedirect' ], 1 );
  }
  public function maybeRedirect(): void {
    if ( is_admin() || wp_doing_ajax() ) return;
    $cached = $this->cache->get( $this->hash( $_SERVER['REQUEST_URI'] ) );
    if ( $cached ) { $this->send( $cached ); return; }      // cache hit
    $match = $this->match( $_SERVER['REQUEST_URI'] );        // 1 query on miss
    if ( $match ) { $this->cache->warm( $match ); $this->send( $match ); }
  }
```

### G.2 Features

- Codes: **301 / 302 / 307 / 410 / 451** (matches RM — `rankmath-audit.md §6c`; Yoast Premium — `feature-matrix.md §3`).
- Exact + regex matching (RM supports both — `rankmath-audit.md §6c`; RM free lacks CSV import, `rankmath-audit.md §6f` — we add it free).
- **CSV import/export** (free; Yoast Premium only, RM free export-only — `feature-matrix.md §3`).
- **Auto-redirect on slug change:** `post_updated` watcher creates a 301 when slug actually changed (mirror RM `Watcher` — `rankmath-audit.md §6e`).
- **404 logger** with prune policy (age + count, oldest-first — see §D.4, fixing RM truncate).
- **1-click "create redirect"** from a 404 log row (RM has this — `rankmath-audit.md §6j`; we adopt).

## H. Schema Design

### H.1 Generator with lazy `is_needed()`

We adopt Yoast's `wpseo_schema_graph_pieces` architecture: a generator assembles one `@graph`, and each piece declares `is_needed()` (`yoast-audit.md §3` schema generation). Pieces: Article, WebPage, Organization, LocalBusiness, FAQ, HowTo, Product, Recipe, Event, Breadcrumb.

```
SPEC (RankKernel\Modules\Schema\Generator):
  public function generate( Context $ctx ): array {
    $graph = [];
    foreach ( $this->pieces as $piece ) {
      if ( $piece->is_needed( $ctx ) ) {        // lazy: only build what the page needs
        $graph = array_merge( $graph, $piece->build( $ctx ) );
      }
    }
    return [ '@context' => 'https://schema.org', '@graph' => $graph ];
  }
```

- **One `@graph`**, emitted as a single `<script type="application/ld+json">`.
- **Lazy per-page assembly** into the single graph; Breadcrumb piece only builds when breadcrumbs are active (ties to §E.3).
- **Storage inside the single meta key** (`schema` array in `_rankkernel_meta_data`), not separate `rank_math_schema_*` rows (`rankmath-audit.md §1` finding 2, §4 — RM stores schema as multiple serialized meta rows, a bloat source).

### H.2 Custom builder UI (free)

A free multi-schema-per-page builder (RM gates the advanced builder behind Pro — `rankmath-audit.md §4`, `feature-matrix.md §4`). `JUDGMENT`: this is a headline "we give it away free" feature; spec only, built in the Gutenberg/AI phase.

## P. Build Order (module-by-module, verification gates)

Aligned to the original roadmap (`Custom WordPress SEO Plugin Blueprint.md` Phases 1–4), with verification gates matching the benchmark protocol (§B.2).

### Phase 1 — Core Foundation (Metadata, Sitemaps, IndexNow, Robots)
1. **Bootstrap + ModuleManager** (`Plugin`, `ModuleInterface`, hard gate). *Gate: phpcs + phpstan pass; module OFF yields zero hooks (asserted by grep of registered hooks).*
2. **Data layer** (single meta key, `register_meta`, options, migrations). *Gate: 1 post-meta row per object; `get_post_meta` count = 1 on render.*
3. **Metadata Engine** (HeadRenderer, TagsReplacer memoized, Context-once). *Gate: ≤1 DB query for meta on a rendered page (Query Monitor).*
4. **XML Sitemaps** (rewrite intercept, providers, cache ON + validator). *Gate: sitemap cache hit serves without rebuild; TTFB overhead ≤1ms on warm cache.*
5. **Instant Indexing (IndexNow)** + **Robots.txt/.htaccess editors** (default OFF). *Gate: publish triggers IndexNow ping; robots edit has backup-first + validation.*

### Phase 2 — Technical SEO Engine (Redirects, 404, Multi-Schema)
6. **Schema/JSON-LD** (lazy `is_needed()`, one `@graph`, stored in meta). *Gate: only needed pieces build; Breadcrumb piece builds only when requested.*
7. **Breadcrumbs + block** (lazy). *Gate: zero breadcrumb queries when not rendered.*
8. **Redirects** (cache-first `template_redirect`, CSV import, slug-change watcher). *Gate: module OFF = zero hooks; cold-miss = 1 query; cache hit = 0.*
9. **404 Monitor** (log + prune-by-age+count + 1-click redirect). *Gate: prune never truncates; history retained to policy.*

### Phase 3 — Gutenberg Content Engine (Analyzer, Social Previews, Importer)
10. **Importer** (detect Yoast/RM/SEOPress, batch 50, dry-run, rollback). *Gate: imported site shows equivalent meta from single row; originals restorable.*
11. **Gutenberg Suite** (React sidebar, unlimited focus keywords, client-side readability, OG/Twitter previews). *Gate: assets enqueued only on editor; zero frontend CSS/JS.*

### Phase 4 — Gap Fillers & AI (BYO-Key, Headless, Image SEO)
12. **AI Suite** (BYO-key provider abstraction, per-user keys, rate guard). *Gate: no external request except to configured provider; key never logged.*
13. **Headless** (REST payload + WPGraphQL-ready fields). *Gate: `/seo/{id}` returns full payload; GraphQL fields register only if WPGraphQL present.*
14. **Image SEO** (bulk alt/title autofill with dynamic tags). *Gate: bulk action processes N=50 batches; no frontend asset.*

### Cross-cutting gates (every phase)
- `phpcs` (WPCS + PSR12) clean.
- `phpstan` level ~6 clean.
- Plugin Check (PCP) passes.
- Benchmark protocol (§B.2) re-run; numbers published in `docs/benchmarks/`.
